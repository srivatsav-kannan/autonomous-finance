# Held-out synthetic supplier/layout originals v1

These four project-authored originals introduce two invented suppliers and two layouts absent from the earlier Golden State PDF corpus. The prior `formats-v1` separate-supplier control was structured XML, not a PDF. This is a small engineering evaluation set, not a representative production benchmark or an independent blind accuracy result.

| Supplier | Layout | Native / scan | Exact authored total |
| --- | --- | --- | --- |
| Harbor Thread Textiles LLC | Landscape textile ledger; reordered quantity/UOM/description/SKU/price columns | `input/harbor-thread-native.pdf`, `input/harbor-thread-scan.pdf` | USD 274.00; fractional roll quantity, USD 12.50 freight, USD 5.35 discount |
| Copper Valve Maintenance Inc. | Portrait service statement; wrapped descriptions and monospace prices | `input/copper-valve-native.pdf`, `input/copper-valve-scan.pdf` | USD 262.50; fractional labor hours |

All names, transactions and references are invented. Every original visibly says it is synthetic and not payable. Each scan is a controlled image-only proxy made from its native original, with grayscale conversion, mild blur/contrast loss and fixed faint streaks. It is not a genuine archival or camera scan. Each file has one page, and the four files total 232,224 bytes. Exact source hashes, page dimensions and provenance are in `manifest.json`.

`generate.py` reads only `authoring/facts.json`. Fixed PDF metadata and deterministic raster transformations make this environment reproducible. It does not read evaluation results, runtime extraction code or provider responses. The project author inspected the existing mapper before creating this set, so the evaluation is held out by supplier/layout, not blind to the implementation.

The independent-from-runtime evaluation key is `evaluation/expected-outcomes.json`. It was separately transcribed and frozen before an actual parser run. It contains 104 visible field facts: 11 header fields per original, plus six fields per line. Native and scanned versions both remain in the denominator, including missing content, null candidates, unresolved geometry or failed parsing. This is author-derived ground truth; independent original-derived review by V is still required. `quantity` compares to `candidate.lines[].quantity.decimal`; `unit` compares to `.quantity.unit`. Match lines by the unique printed SKU, not runtime line IDs.

Only the original bytes, source provenance and `runtime-contexts.json` may enter runtime requests. Those contexts contain an approved supplier identity and coding dimensions, without invoice identifiers, amounts, quantities or expected extraction. Parse the four files as four separate cases. The two versions of each invoice deliberately represent the same economic document. Do not ingest them together as separate payable invoices. No PO, receipt or contract is supplied; printed reference strings establish neither receipt nor business acceptance.

## Reproduce and inspect

Measured environment: Python 3.12.14, ReportLab 4.4.9, Pillow 12.3.0, pypdf 6.10.0 and Poppler 26.02.0. Install/use those existing local tools; no provider access is needed.

```sh
python3 fixtures/ap-system/heldout-suppliers-v1/generate.py /tmp/ap-heldout-reproduce
python3 fixtures/ap-system/heldout-suppliers-v1/evaluation/verify-originals.py
```

Compare the regenerated four `input/` files, `manifest.json` and `runtime-contexts.json` byte-for-byte with this directory. The evaluation key is intentionally not generated by this command. Render each original with `pdftoppm -r 100 -png -singlefile INPUT.pdf OUTPUT_PREFIX` and inspect all four pages. The author checked readable values, intact labels/totals, wrapped descriptions, margins and synthetic footers; no clipping or overlaps were found. The evaluation verifier checks hashes, page/crop dimensions, zero rotation, native printed facts, exact decimal arithmetic and the absence of native text in both scan PDFs. It performs no OCR or parser call and cannot establish scan extraction accuracy.

Master runs the actual existing `parseUpload` adapter with a separate private storage root, fixed source IDs/revisions, exact original provenance and matching runtime contexts. Keep provider artifacts private; retain artifact hashes/config/version references in evaluation evidence. Do not feed `authoring/` or `evaluation/` into the parser. Record content and geometry separately for all four originals. Actual parser results and independent acceptance are pending.
