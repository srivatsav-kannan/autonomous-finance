# Isolated local multi-human identity seam

Engineering checkpoint only. This adapter does not create a backend, enroll real people, authenticate with an IdP, approve a real payment, or start a bank worker. Master owns the separate local3254/3255 runtime, gateway8826 and UI5193 lifecycle. Existing I1 deployment3250/3251 and external Auth0 sandbox3252/3253 are not configured or changed by this contribution.

`createAPLocalSimulationAuthentication({scope,convexUrl,actors,serviceForActor,authorizeActor})` lives in `src/ap-system/local-simulation-auth.ts`. It requires exact `http://127.0.0.1:3254`, fake/local scope and an owned ap97 run. Actor IDs and simulated subjects must be distinct; public config exposes only IDs/names. Only `local:<configured actor ID>` is accepted in this local adapter. Missing or failed per-request `authorizeActor` returns approved=false. Root should run current `apIdentity:workspaceAccess` with that actor's fresh simulated human client on each call, and `serviceForActor` must supply a fresh request-owned service. No admin key is present in this adapter or browser.

The Auth0 adapter explicitly rejects local selection tokens before constructing a human client. The same HTTP origin/CSRF and subject-bound session rules apply to local simulated actors: a cookie established for actorA cannot authorize actorB. Every protected route resolves the current actor and current binding. The no-auth legacy local branch remains unchanged.

The browser accepts local_simulation config only with simulated_human readiness on exact UI origin `http://127.0.0.1:5193`. A persistent visible banner says “Local multi-human simulation / FakeBank,” explains the identities are simulated, and requires an explicit actor selection before mounting the workspace. Selection lives in memory only; no JWT is pasted or persisted. Changing/clearing an actor immediately aborts pending requests and hides/unmounts old case data. Each actor establishes a fresh subject-bound list session. The selector is disabled while a workspace mutation is busy. Periodic current-binding checks hide the workspace after revocation.

Validation: 40 focused auth/HTTP/render tests pass; main/tests typechecks, console build and static design check pass (0 FAIL/0 WARN). Tests cover isolated host/provider guard, distinct actors, unknown selection, absent/revoked binding, per-request service ownership, public config redaction, Auth0 rejection, cross-actor cookie/write denial, stale response rejection and loading/banner behavior. Real isolated-backend/browser journey remains Master-owned follow-up; fixture/static success is not that acceptance.
