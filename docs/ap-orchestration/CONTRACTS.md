The executable wire contract is `src/ap-system/contracts.ts`. Supplier AP is separate from the existing customer invoice MVP. All record identities are scoped by organization/run; database-generated IDs remain opaque strings at the HTTP boundary. Hashes are lowercase SHA256 of original bytes or canonical snapshots, never filenames. Source revisions and deliveries are separate: a renamed duplicate adds a delivery association, not a second obligation. Explicit revisions retain prior documents/decisions and invalidate current review. A source/field reference always binds sourceId + revision + sha256.

Money is nonnegative safe integer USD cents. Quantity is an exact decimal string plus unit, with at most six places; use integer/rational arithmetic and round half up once per line. Unknown values remain null. Line amountCents is pre-tax; line taxCents is separate. Subtotal is the sum of line amounts, header tax is the sum of line tax. Each line allocation sums to line amount + line tax. freightAllocations sum to freightCents and discountAllocations sum to discountCents (discount postings reverse the allocated cost). Thus total = subtotal + tax + freight - discount. Zero allocations cause a coding hold, not inferred account 5000. Backend verifies these rules with exact integer arithmetic. Invoiced, accepted, disputed, credited, instructed, settled and outstanding are distinct. No adjustment follows solely from a model recommendation.

Geometry has independent content and location states. Native -> exact unique raw words -> bounded local OCR -> unresolved. Derived rectangles must retain matched token references and word/line granularity; multiline evidence has separate regions. Frames use original page coordinates, top-left origin, explicit pixels/points, orientation and affine display transform. Context regions are labeled coarse context and cannot substitute for precise fields. Preserve requested and resolved processor versions; unresolved provider versions stay null. `latest` does not count as a reproducible resolved version. XML evidence retains element paths. Failed/missing pages prevent a complete reviewed candidate. Ingest and case detail allow candidate:null with extraction status incomplete/failed, individual field evidence and explicit reasons; these sources remain persisted/countable and cannot progress to bill approval. Unknown invoiced amount stays null. Processor metadata links hashed raw/config/token/raster artifacts and OCR traineddata language/version/hash; private artifact refs are server-side and never signed URLs in committed reports.

## Policy and evaluation

Policy version golden-state-ap-v1: zero unexplained price/quantity variance for first packet; missing receipt, unknown SKU/unit, content conflicts and incomplete pages hold. Missing precise geometry alone may proceed only after explicit human field review of the correct original source/text, with that review retained. Valid geometry alone never approves business facts. Explicit authorized supporting evidence may resolve a hold; simulated notification is never a sent communication. AP practitioner review remains a separate external gate.

FixtureManifest/ExpectedOutcome are frozen separately from parser output. Unresolved cases stay in denominators. Independent verifier reviews originals and policy-derived expected outcomes, records identity/version, and never labels its own agent review as practitioner review. Frozen contract amendments require Master approval and registry evidence before downstream edits depend on them.

## Dispatch clarifications

First-wave bill approval requires acceptedCents === candidate.totalCents. Partial acceptance/adjusted allocations are B3 and need a separately versioned command; an amount-only approval must never silently reallocate. Candidate evidence must resolve to exactly the original source triple; each line evidenceId must resolve, and every tokenRef is checked against the hashed token artifact's same source/page/revision. pageStatus covers exactly 1..pageCount. Precise regions are word/line/cell; page/table belong only to contextRegions. The invertible frame transform maps original page coordinates to display coordinates; OCR raster-to-original-page transformation is recorded in the hashed processor configuration, before those regions enter this contract.

Canonical review snapshot is SHA256 of recursively key-sorted JSON containing contractVersion, candidate (including allocations and source bindings), extraction, purchasingEvidence, documents' source bindings and page statuses, and policyVersion. It excludes mutable timeline, decision timestamps and payment observations. Source additions or corrections create a new case revision, snapshot and retained evidence history. Exception resolution in wave one is via new supporting evidence/revision followed by fresh field/business review; no free-form clear-flags endpoint.

Original route: GET /api/ap-system/sources/:sourceId/revisions/:revision?sha256=<hash> checks session/run and exact binding, returns original bytes with recorded MIME. Clients never navigate originalRef. HTTP rejection shape is {error:{code:string,reason:string}}. links.commandIds are existing EffectIds (demoCommands._id); payments.commandId has that same meaning. payments.providerTransferId is separate. Payment detail reads at GET /api/ap-system/payments/:versionId expose approved snapshot, approvals, bank observations/transactions and journal links after scope authentication; the response uses existing typed PaymentSnapshot, PaymentApproval, TransferObservation and BankTransaction contracts with only safe fields. This endpoint is Master/C integration ownership.
