# Extraction follow-up protocol — 2026-10-24

This additive protocol is committed before the new real-backend run. It preserves all earlier reports, sealed run IDs and spend ledgers. This follow-up uses zero model calls and no new API budget. The implementation is based on main `27680f6`.

1. Run the public development corpus in `tests/fixtures/invoice-extraction.ts` against the old parser from `27680f6` and the new parser. It was authored alongside this implementation and is a regression check, not unseen accuracy. Each case checks the declared fields/treatment and required warnings; source quotation validity is separate. Test exact cents, customer/alias collisions, total/balance distinctions, credits, mixed currencies, multi-document sources, revisions and ambiguous text.
2. Run the pinned original Invoice Sandbox fixture through the unchanged deterministic HTTP evaluator, into a fresh real Convex workspace. The original fixture is previously seen. Label the run post-fix. No automatic human decisions or model calls. Require clean source-commit attestation, original bytes/text retention and persisted final snapshots.
3. Run the unmodified official scorer and existing contribution audits on those snapshots. Do not substitute proposals for accepted totals.
4. Independently score persisted proposal customer ID, document number and absolute printed total against the pinned document key using `score_extraction.py`. Report exact candidate-field matches and coverage of eligible invoice/credit contributions. Also report every ineligible document with a financial candidate and its accepted effect count. A warning-bearing proposal for a duplicate or superseded document is not a correct accepted contribution. This is a supplemental extraction metric, not official accuracy.
5. Verify an isolated browser/API workflow with public synthetic sources: extract a non-routine invoice and signed credit, inspect original quotations, require a human decision, replay without duplicate effects, and retain conflicting fields as unresolved.

Dollar symbols alone produce a currency warning requiring human confirmation; they do not establish USD. The routine backend auto-accept grammar remains narrow. The new extractor never supplies automatic acceptance of arbitrary PDF layouts. There is no new held-out or live-model result and no claim about OCR accuracy: PDF text is still supplied upstream. The old held-out suite is not used to tune this follow-up.
